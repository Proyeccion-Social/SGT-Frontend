Guía del proyecto: SGT-Frontend (Astro)

Objetivo: explicarte qué es cada carpeta/archivo, cómo se conecta todo y para qué sirve (nivel principiante).

1) ¿Qué es este proyecto?

Este repo es el frontend del “Sistema de Agendamiento de Tutorías”. Está hecho con Astro y usa React solo para algunas piezas (por ejemplo, el toaster de notificaciones).

La idea principal:

  • Páginas (rutas) en src/pages/.
  • Layouts (plantillas comunes) en src/layouts/.
  • Features (módulos por funcionalidad) en src/features/.
  • Conexión al backend con patrón tipo BFF: el frontend llama a /api/... (endpoints internos Astro) y esos endpoints llaman al backend real usando API_URL.

2) Cómo se corre (modo dev/build)

En package.json están los scripts:

  • npm run dev → levanta el servidor local.
  • npm run build → genera el build.
  • npm run preview → previsualiza el build.
Nota: existe pnpm-lock.yaml, así que el equipo probablemente usa pnpm. Con npm también puede funcionar según el entorno.

3) Estructura general del repo

Archivos raíz

  • astro.config.mjs: configuración de Astro (incluye React).
  • tsconfig.json: TypeScript + alias (@/, @features/, etc.).
  • docs/: documentación interna.

Carpetas principales

  • public/: assets servidos tal cual.
  • src/: el código.

4) src/ explicado

4.1) src/pages/ — Rutas (URLs)

En Astro, cada archivo dentro de src/pages crea una ruta:

  • src/pages/index.astro → /
  • src/pages/dashboard.astro → /dashboard
  • src/pages/auth/login.astro → /auth/login
  • src/pages/auth/register.astro → /auth/register

4.1.1) src/pages/api/ — API interna (BFF)

Endpoints server-side dentro del frontend:

  • src/pages/api/auth/login.ts
  • src/pages/api/auth/register.ts
  • src/pages/api/auth/recover-password.ts
  • src/pages/api/auth/validate-email.ts
  • src/pages/api/auth/logout.ts (pendiente)

Se consumen desde el navegador con fetch("/api/auth/...").

¿Por qué existe? Para guardar tokens en cookies httpOnly, evitar CORS y centralizar errores/respuestas.

4.2) src/layouts/ — Plantillas

  • src/layouts/Layout.astro: HTML base + carga src/styles/global.css.
  • src/layouts/auth/AuthDialogLayout.astro: layout para <dialog> + toaster.
  • src/layouts/auth/AuthDialogsContainer.astro: backdrop compartido para varios diálogos.
  • src/layouts/dashboards/*.astro: layouts por rol (con data mock).
Detalle a corregir: src/pages/auth/register.astro importa @/layouts/AuthLayout.astro, pero ese archivo no existe. Probablemente quedó un import antiguo.

4.3) src/features/ — Módulos por funcionalidad

  • Landing (src/features/landing): componentes del home.
  • Auth (src/features/auth): formularios/diálogos + services al backend.
  • Dashboards (src/features/dashboards): sidebar/cards/badges.

4.4) src/styles/ — Reset + tokens

  • global.css: reset, fonts, estilos de sileo.
  • variables.css: variables de diseño (colores, tamaños, breakpoints).

5) Conexión con backend (paso a paso)

5.1) Variable API_URL

Los services (por ahora, de auth) usan:

const API_URL = import.meta.env.API_URL;

Si API_URL no existe, las llamadas al backend fallan.

5.2) Flujo de login actual

  1. UI valida email: POST /api/auth/validate-email.
  2. UI hace login: POST /api/auth/login.
  3. El BFF llama al backend real: POST ${API_URL}/auth/login.
  4. El BFF guarda cookies httpOnly: access_token y refresh_token.
Como las cookies son httpOnly, JS no puede leerlas, pero el navegador sí las envía automáticamente en requests al mismo dominio.

6) Mapa mental (cómo se conectan las piezas)

  • Página (src/pages) arma pantalla y llama layouts/features.
  • Layout (src/layouts) envuelve estructura común.
  • Componente (src/features) implementa UI/lógica cliente.
  • BFF (src/pages/api) corre server-side y habla con backend real.
  • Service (src/features/*/services) encapsula fetch al backend usando API_URL.

7) Checklist de depuración rápida

  • ¿Corre npm run dev sin errores?
  • ¿Está definida API_URL?
  • ¿Responde el backend (ej. ${API_URL}/auth/login)?
  • Si un modal no abre: revisa atributos data-open-login/data-open-registry y scripts del dialog.
  • Si una ruta 404: revisa que exista el archivo en src/pages.
